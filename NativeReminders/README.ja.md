# Appleリマインダー連携：日本語の更新手順

新しく導入する場合は、[利用者向け導入手順](README.public.ja.md)を参照してください。ここでは既に連携を利用している方向けに、補助アプリをメモ短縮版へ更新する手順を説明します。**拡張機能の再読み込みだけでは、補助アプリは更新されません。**

更新後のメモは、次の2行になります。画面幅によっては折り返して表示されます。

```text
アルゴリズム論
WC_SYNC_ID:wc_v1_0123456789abcdef
```

元の課題名・締切などの同期情報はMac側に保存し、現在の期限とリンクはリマインダー標準の欄を使います。課題名・締切・完了状態の同期ルールは維持します。

## 必要なもの

- macOS 14以降のMac（Apple Silicon／Intel共通の手順）。
- Google Chromeと、現在利用しているANTI-WebClass拡張機能。
- 今回の変更を含むリポジトリのソースコード。
- Xcode Command Line Tools。既に補助アプリをビルドできていれば、その環境を使用できます。

この手順は開発版を自分のMacでビルド・更新する方法です。一般配布用のインストーラーは使用しません。

## 1. 同期を停止する

1. 実行中の同期があれば、完了するまで待ちます。
2. 拡張機能の設定で「外部ToDoと連携する」をOFFにします。
3. 拡張機能の設定画面を閉じます。

リマインダーの「WebClass」リストや既存の課題は削除しないでください。拡張機能の削除・入れ直しや、補助アプリのアンインストールも不要です。

## 2. 現在の拡張機能IDを確認する

Chromeのアドレス欄に `chrome://extensions` を入力し、デベロッパーモードをONにして、ANTI-WebClassの「ID」をコピーします。

IDは英小文字32文字です。更新時も**現在利用中の拡張機能と同じID**を使います。テスト用の `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa` は使わないでください。

## 3. 同期情報をバックアップする

拡張機能の設定から、必要に応じてToDoデータを含めた設定バックアップを保存します。保存後は設定画面を閉じてください。

さらに、Finderの「移動」→「フォルダへ移動」で次の場所を開きます。

```text
~/Library/Application Support/ANTI-WebClass/Reminders/
```

`metadata-拡張機能ID.json` があれば、別の場所へコピーして保管してください。**拡張機能の設定バックアップには、このファイルは含まれません。**

初めて0.2.0へ更新する場合、このJSONファイルがまだ存在しなくても正常です。初回の移行後に作成されるので、手順6の確認後にもバックアップしてください。

## 4. 補助アプリをビルド・インストールする

ターミナルを開き、リポジトリのルートへ移動します。別の場所に保存している場合はパスを変更してください。

```sh
cd ~/dev/ANTI-WebClass-Dev
```

次の引用符の中を、手順2で確認した実際のIDに置き換えて実行します。以降は同じターミナルで作業してください。

```sh
REMINDERS_EXTENSION_ID='ここを実際の32文字の拡張機能IDに置き換える'
```

ビルドします。

```sh
bash NativeReminders/scripts/build.sh "$REMINDERS_EXTENSION_ID"
```

**エラーが出た場合はインストールへ進まず、原因を解消してください。** 成功すると、生成した `WebClass Reminders.app` のパスが最後に表示されます。

続けてインストールします。

```sh
bash NativeReminders/scripts/install.sh "$REMINDERS_EXTENSION_ID"
```

次のメッセージが表示されればインストールは完了です。

```text
Installed. Open extension settings and connect Apple Reminders.
```

補助アプリは `~/Applications/WebClass Reminders.app` に上書きされます。既存のリマインダーや同期情報は削除されません。補助アプリをFinderから手動で起動する必要はありません。

## 5. 拡張機能を再読み込みして同期を再開する

1. `chrome://extensions` でANTI-WebClassの再読み込みボタンを押します。
2. 拡張機能の設定を開き、「外部ToDoと連携する」をONにします。
3. 連携先が「Appleリマインダー」になっていることを確認します。
4. 「状態を確認」を押します。未接続なら「Appleリマインダーに接続」を押し、アクセス要求が出た場合は許可します。
5. ログイン済みのWebClassホーム画面を1つ開き、必要ならそのページを再読み込みしてから、通常のToDo同期を1回実行します。

複数のWebClassページで同時に更新操作をしないでください。最初の同期が完了するまで待ちます。

## 6. メモが短くなったことを確認する

Macのリマインダーで「WebClass」リストを開き、次の項目を確認します。

- メモが「短い科目名＋`WC_SYNC_ID`」になっている。
- 課題名・期限・完了状態が意図した状態になっている。
- 課題のリンクが標準のURL欄に残っている。
- 同じ課題が重複して増えていない。

既存の長いメモは、同期中に詳細情報をMacへ保存してから短縮します。完了済みの同期対象も移行します。保存に失敗した課題のメモは短縮せず、エラーで同期を止めます。

続けてiPhone側を確認します。iPhoneにも表示されるアカウントのリストを使用している場合、通常のアカウント同期後に変更が反映されます。Macだけ先に短くなっている場合は、アカウントの同期状態を確認してください。

最後に、手順3のJSONファイルをバックアップします。同期IDの行は課題の対応付けに必要なので、削除しないでください。

## うまくいかない場合

| 状況 | 確認すること |
|---|---|
| ビルドでツールが見つからない | Xcode Command Line Toolsが必要です。未導入なら `xcode-select --install` で導入し、完了後に再実行します。 |
| `Usage: ...` と表示される | IDが英小文字32文字になっているか確認します。ビルドのIDは省略できますが、インストール時には必要です。変数設定も同じターミナルで実行してください。 |
| `Rebuild for this extension ID first.` と表示される | 古いスクリプトを使っている可能性があります。今回のソースの `build.sh` と `install.sh` を使って同じIDでやり直すか、利用者向けZIPのインストーラーを使います。 |
| 補助アプリが見つからない・接続できない | インストールが成功したか、Chromeの拡張機能IDとビルド時のIDが同じかを確認します。 |
| アクセス権限のエラー | macOSのシステム設定で、プライバシーとセキュリティのリマインダー権限を確認し、拡張機能から再接続します。更新後に再許可が必要になる場合があります。 |
| 別の同期が実行中と表示される | 先の同期や接続確認が終わるのを待ち、再試行します。 |
| メモが長いまま | 拡張機能だけでなく、補助アプリも今回のソースで再ビルド・インストールしたか確認し、その後に同期します。 |
| Mac側の同期情報の保存・読み込みエラー | 同期を停止し、バックアップと保存先を確認します。破損したJSONを削除してエラーを回避するのではなく、同期を止めた状態で正常なバックアップから復元してください。 |

JSONファイルを失っても、同期IDとURLが残っていれば課題を照合できる場合があります。ただし、元の課題名・元の締切を完全には復元できない場合があります。また、メモ短縮後に古い補助アプリへ戻すと、新しい保存形式を読み取れません。移行後のダウングレードは避けてください。
